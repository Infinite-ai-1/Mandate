# Mandate frontend

React + Vite + TypeScript, Tailwind and Recharts. The only production data source
is `/api`. All portfolio numbers come from API fields; percentage/currency
formatting changes units only. No market fetches, LLM calls, CDN fonts or
external assets. Successful API responses are validated before being cached
in memory and local storage, per resource and charity. Failed reads retain the
last good data and show a warning. No synthetic fallback exists in the app.

## Run and build

In `frontend/`: `npm ci`, then `npm run dev` (proxy `/api` to localhost:5000).
`npm run build` writes `frontend/dist`. `npm test` runs boundary and component
tests. Dependencies are locked in `package-lock.json`.

At repository root, install `quant/requirements.txt` plus Flask. When Person 2's
`api.py` exposes `app`, `python -m frontend.serve` serves the real app and built
frontend together on 127.0.0.1:5000. Alternatively call
`frontend.flask_static.register_frontend(app)` from the API owner's startup.
The adapter handles SPA routes and assets; unknown API routes stay JSON 404s.
Neither shared `api.py` nor `pipeline.py` was edited.

## Computed headline totals without changing JSON schemas

The Flask adapter adds an optional `X-Mandate-Presentation` response header to
portfolio and selection GETs. `quant/presentation.py` calculates it on the
server. It contains `total_gbp`, `holdings_count`, `shares_weight`, `bonds_weight`,
`cash_weight`, or `analysed_count` respectively. The original JSON body is
unchanged. `gbpusd` means USD per GBP. The frontend only formats these values;
it never sums weights, counts holdings or converts money. If this adapter has
not been registered, the page explicitly omits those unavailable totals.

## Offline synthetic integration preview

Person 2's stub API, `stubs/`, shared models, registry, policies, ingest output
and real API were absent in the supplied checkout. To exercise the owned areas
without changing anybody else's files, `python -m frontend.dev.stub_api` at repo
root starts an explicit synthetic-only fixture server on 127.0.0.1:5000 and
serves the build. Its data is generated by the quant optimiser, validated with
strict test-only contract models and labelled with `X-Mandate-Data: synthetic`.
The UI displays a synthetic-data banner. This server never reads API keys and
never calls a network service. Judge-rule effects and agent scores are simulated
and explicitly marked as fixtures, not agent evaluations or actual charity rules.

`python -m frontend.dev.export_fixtures` rebuilds `dev/fixtures.json` for component
tests. `python -m unittest quant.test_stats quant.test_portfolio frontend.dev.test_api`
checks calculations, all four fixtures, source resolution, live-rule/refresh
jobs with networking forbidden, and Flask serving the production assets.
`dev/.cache/` contains generated local portfolio outputs and is ignored by Git.
